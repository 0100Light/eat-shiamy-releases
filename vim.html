vim 模式　接線說明

讓編輯器在離開 insert mode 時把嘸蝦米整個停用，回去再恢復。

先打 ,,vim 把 vim 模式開起來（右鍵選單的 vim 模式 也有）。沒開的時候程式不聽任何連接埠， 底下所有設定都不會有反應。開起來的那一刻嘸蝦米就直接停用了 （等於編輯器送了一個 off 進來），回到 insert mode 時由下面的 接線把它叫回來。功能本身怎麼用寫在 使用說明的「vim 模式」那一節。

它是怎麼運作的

嘸蝦米不會去猜編輯器在做什麼，而是開一個開關等編輯器來按。

vim 模式開著的時候，程式在你自己這台電腦上（127.0.0.1， 別台機器連不到）聽一個很小的網頁伺服器，預設在 5599 埠。 任何發得出 HTTP GET 的東西都按得動它 —— curl、編輯器內建的 TCP 函式、一行 shell script 都可以。

所以「支援哪些編輯器」這個問題其實不成立：只要你的編輯器能在 切換模式的時候執行一點東西，就接得上。 這一節講的就是那點東西 要送什麼。看得懂這一節，底下那幾家的設定只是同一件事的不同寫法。

三個代碼

代碼意思什麼時候送
off把嘸蝦米整個停用。鍵盤完全回到原生， 一顆鍵都不攔離開 insert mode
zh啟用，中文模式進入 insert mode
en啟用，英數模式進入 insert mode， 而且你離開前是英數

normal mode 要送的是 off，不是 en。 英數模式在半形的時候確實也不攔鍵，但切到全形就會攔掉整排 ASCII， hjkl 照樣壞掉。off 是唯一無條件不攔鍵的狀態。

兩條網址

網址做什麼回你什麼
http://127.0.0.1:5599/im問「現在是哪個狀態」 off、zh 或 en
http://127.0.0.1:5599/im/off設成那個狀態 設定之前的狀態

讀那一條是選用的。有讀的話就能做到「離開 insert mode 前先記下你是中文 還是英數，回來時還原」；不讀的話回來一律變成中文。

其餘的回應碼：

情況回
沒帶 Host，或它指的不是本機的這個埠403
看起來是瀏覽器發的（見下面第二條規則）403
網址形狀不對404
代碼不是那三個400
不是 GET501

四條規則

自己接的時候會踩到的就是這四條。它們全部的失敗方式都一樣： 完全沒反應，而且不會有任何錯誤訊息（因為送請求的那一端通常 根本不去讀回應）。

  1. 一定要帶 Host 標頭。 curl 之類的工具會自己補，但你如果是自己開 TCP 寫一段 請求文字，就得自己寫上去：

    GET /im/off HTTP/1.0
Host: 127.0.0.1:5599

    少了它一律回 403。這是擋「把別的網域解析到 127.0.0.1」那種攻擊的， 不能省。換過連接埠的話這一行的號碼也要跟著改。

  2. 瀏覽器發的請求一律拒。 有 Origin、Referer 或任何 Sec-Fetch- 開頭的標頭就回 403。所以不能在瀏覽器的網址列貼上那個網址來測試， 它一定失敗。理由見安全性那一節。

  3. 回應的內容結尾沒有換行。 讀狀態那條回的就是 zh 三個字元，乾乾淨淨。有些編輯器會拿這個字串去跟上次記下的 比對，多一個換行就會被判成「換了輸入法」而每次都重切。

  4. HTTP/1.0，一次請求就關。 不必處理 keep-alive， 送完讀完就把連線關掉。

要多快才夠

你按下 Esc 之後大約 100 到 300 毫秒就會按下一個鍵。 切換要在那之前做完，不然那顆鍵會被吃掉。

做法大約要多久結論
編輯器內建的 TCP 函式直接連1 毫秒以內最好
執行 curl.exe約 25 毫秒夠用
執行一個大程式（例如嘸蝦米自己的 exe）約 200 毫秒 來不及，會漏鍵

所以優先順序是：編輯器能直接開 TCP 就直接開，不行才退回去跑 curl。底下那幾節就是照這個順序排的 —— 排在前面的比較快，也比較推薦。

curl 那條在實際使用上摸得出一點延遲：每切一次模式就要啟動 一次程式，而你按 Esc 之後往往馬上就按下一個鍵。功能是好的， 只是手感沒有直接連的那麼跟手。

先確認開關是通的

在 PowerShell 或命令提示字元裡跑（不要用瀏覽器）：

curl.exe -s http://127.0.0.1:5599/im

印出 zh、en 或 off 就是通的。 什麼都沒印出來，多半是 vim 模式沒開，或者連接埠不是 5599。

想看得更清楚就加 -v，它會把送出去的標頭跟回應碼一起印出來 —— 查 403 的時候很有用。

照這個原理接任何編輯器

底下列的幾家是實際測過的。你的編輯器不在裡面也沒關係，三個步驟：

  1. 找到掛鉤的地方。 你的編輯器在「離開 insert mode」與 「進入 insert mode」的時候，有沒有辦法叫你指定的東西？可能叫 autocmd、 event、hook，也可能是一個「切換輸入法用的指令」設定項。很多 vim 模擬器 都有最後這個，因為它們本來就是為了接 im-select 之類的工具 而做的 —— 那個位置直接填我們的網址就好。
  2. 決定怎麼送。 能直接開 TCP 就自己組那幾行請求文字 （記得 Host）；只能跑外部指令就用 curl.exe -s 網址。
  3. 接上去。 離開 insert mode 送 /im/off， 進入時送 /im/zh。想要「回去時還原成原本的中英狀態」， 就在離開前先讀一次 /im 把結果存起來，回來時送那個值。

接完之後照這張清單檢查一遍，這幾項全是真的害人查過半天的：

  • vim 模式開了嗎（狀態列右邊那一格要是 Vi）
  • 連接埠對嗎（預設 5599）
  • 自己組的請求有沒有帶 Host
  • 要跑外部指令的話，有沒有寫完整的路徑 —— 有些編輯器不會去 PATH 裡找，只寫 curl.exe 會被它判定成 「這個檔不存在」
  • 是不是用瀏覽器在測（一定被擋）
  • 離開 insert mode 送的是 off 而不是 en

Neovim

最推薦的接法。 用內建的 vim.uv 直接開 TCP， 不必啟動任何外部程式，一毫秒以內就切完了，手上完全感覺不到。 放進 init.lua：

local PORT = 5599

local function shiamy(code)
  local pipe = (vim.uv or vim.loop).new_tcp()
  if not pipe then return end
  pipe:connect('127.0.0.1', PORT, function(err)
    -- 連不上就安靜放棄（多半是 vim 模式沒開）
    if err then pipe:close() return end
    local req = 'GET /im/' .. code .. ' HTTP/1.0\r\n'
             .. 'Host: 127.0.0.1:' .. PORT .. '\r\n\r\n'
    pipe:write(req, function()
      pipe:shutdown(function() pipe:close() end)
    end)
  end)
end

local grp = vim.api.nvim_create_augroup('shiamy', { clear = true })
vim.api.nvim_create_autocmd({ 'InsertLeave', 'CmdlineLeave' }, {
  group = grp, callback = function() shiamy('off') end,
})
vim.api.nvim_create_autocmd('InsertEnter', {
  group = grp, callback = function() shiamy('zh') end,
})
vim.api.nvim_create_autocmd('VimEnter', {
  group = grp, callback = function() shiamy('off') end,
})

三個掛鉤各有各的理由：InsertLeave 是主角； CmdlineLeave 是因為 : 後面打的是指令不是中文； VimEnter 是因為開檔的當下就是 normal mode，卻不會有任何 InsertLeave 發生 —— 少了它，上一個程式留下的狀態會一直帶著走。

這一段刻意不記憶「剛剛是中文還是英數」。要的話就在 InsertLeave 裡先讀一次 /im 存起來， InsertEnter 時送回去。

VS Code ＋ VSCode Neovim

這個外掛（asvetliakov.vscode-neovim）底下跑的是真的 Neovim， 所以走上一節的 init.lua 就好， 寫法一模一樣，速度也一樣快。

設定檔放在 Neovim 的標準位置，Windows 上是 %LOCALAPPDATA%\nvim\init.lua（在 nvim 裡打 :echo stdpath('config') 可以問出來）。除非你在 settings.json 裡設過 vscode-neovim.neovimInitVimPaths.win32 指到別的地方。

VSCodeVim 那四行 vim.autoSwitchInputMethod.* 對它沒有用。 那是 VSCodeVim 自己定義的設定名稱，這個外掛從頭到尾不會去讀它。 貼了不會有錯誤訊息，也不會有任何反應 —— 這是最容易被誤會成「連線壞了」 的一種狀況。

同一份 init.lua 在獨立跑的 Neovim 底下也會生效， 不必為了 VS Code 另外抄一份。只想在 VS Code 裡生效的話， 把整段包進 if vim.g.vscode then ... end。

傳統 Vim 8 / 9

ch_open() 只吃 TCP，正好：

let s:port = 5599
function! s:Shiamy(code) abort
  try
    let ch = ch_open('127.0.0.1:' . s:port, {'mode': 'raw', 'waittime': 50})
    call ch_sendraw(ch, "GET /im/" . a:code . " HTTP/1.0\r\n"
          \ . "Host: 127.0.0.1:" . s:port . "\r\n\r\n")
    call ch_close(ch)
  catch
  endtry
endfunction
augroup shiamy
  autocmd!
  autocmd InsertLeave,CmdlineLeave * call s:Shiamy('off')
  autocmd InsertEnter * call s:Shiamy('zh')
augroup END

VS Code ＋ VSCodeVim

VS Code 上有兩個名字很像、但完全不相干的 vim 外掛，設定方式不一樣。 這一節是給 VSCodeVim（識別碼 vscodevim.vim）的。 如果你裝的是 VSCode Neovim（asvetliakov.vscode-neovim）， 底下這四行對它完全無效 —— 貼了不會有錯誤訊息也不會有任何反應， 請改看前面那一節。

不必另外裝任何東西。VSCodeVim 本來就有「自動切換輸入法」的設定， 把這四行貼進 settings.json：

這一條會有一點延遲。 VSCodeVim 只能執行外部指令，所以每切 一次模式就要啟動一次 curl.exe（約 25 毫秒）。功能是好的， 只是手感沒有直接連的那麼跟手。很在意的話， VSCode Neovim 走的是直接連那條路。

"vim.autoSwitchInputMethod.enable": true,
"vim.autoSwitchInputMethod.defaultIM": "off",
"vim.autoSwitchInputMethod.obtainIMCmd": "C:\\Windows\\System32\\curl.exe -s http://127.0.0.1:5599/im",
"vim.autoSwitchInputMethod.switchIMCmd": "C:\\Windows\\System32\\curl.exe -s http://127.0.0.1:5599/im/{im}"

curl.exe 是 Windows 內建的，不必下載。 {im} 要原樣留著，那是 VSCodeVim 自己會填進去的欄位。 貼完重新載入視窗（Ctrl+Shift+P → Reload Window）。

路徑要寫全，而且反斜線要打兩個。 VSCodeVim 會拿指令開頭 那個字去確認檔案在不在，但它不會去 PATH 裡找。只寫 curl.exe 的話它會判定你設定錯了，然後把整個功能 自己關掉，而且不會有任何提示 —— 症狀是切模式完全沒反應， 看起來很像連不上。

四行都要貼。 少了 obtainIMCmd 那一行， VSCodeVim 就記不住你剛剛是中文還是英數，每次回到 insert mode 都會停在英數。

WSL 裡的 vim

只有 Windows 11 的鏡像網路模式連得到。 在 %USERPROFILE%\.wslconfig 裡寫：

[wsl2]
networkingMode=mirrored

然後跑 wsl --shutdown。這樣 WSL 裡面的 127.0.0.1 才會是 Windows 這邊的同一個，上面那幾段設定就能 原封不動地用。

預設的 NAT 模式下連不到。我們刻意不讓這個開關對整個 區域網路開放 —— 那樣確實可以省掉這一行設定，但代價是同一個網路上的 任何人都按得動你的輸入法，不划算。

換一個連接埠

預設是 5599。萬一那個號碼被別的程式佔走了， 右鍵選單的 vim 模式 第一行會直接告訴你開不起來。

換一個號碼：關掉嘸蝦米，用記事本打開程式資料夾裡的 plugin\window_config.json，把 vim_port 改成別的 數字（例如 5600），存檔後重開。 編輯器設定裡的號碼也要一起改，包括自己組請求時那一行 Host。

把它設成 0 就是把這個功能整個關掉，,,vim 從此不會有反應。

打不通的時候

這個功能所有的壞法都長得一樣：完全沒反應，而且沒有任何錯誤訊息。 所以照順序查：

先確認怎麼看
vim 模式開了沒狀態列右邊那一格是不是 Vi。每次啟動都是關的，要自己打 ,,vim
開關本身通不通在終端機跑 curl.exe -s http://127.0.0.1:5599/im，看有沒有印出狀態
編輯器真的有送出東西嗎把那條指令貼到終端機裡自己跑一次。 跑得動就代表問題在編輯器那一端，不在網路
回應是不是 403加 -v 重跑一次。bad host 就是第一條規則那個 Host 沒帶
VS Code：裝的是哪個 vim 外掛兩個外掛的設定名稱不通用。 VSCode Neovim 與 VSCodeVim 各有一節
VSCodeVim：指令寫的是完整路徑嗎只寫 curl.exe 會讓它把整個功能自己關掉
連接埠對不對右鍵選單的 vim 模式 會把目前生效的號碼寫出來

normal mode 的時候 ,,vim 是打不出來的 —— 那時鍵盤完全還給編輯器了，而 vim 模式一開起來就是這個狀態。 要關掉請直接點狀態列那一格 Vi、用右鍵選單， 或者先回到 insert mode 再打一次。點那一格關掉的時候會順便把鍵盤要回來。

安全性

這個開關沒有密碼。 該講清楚它換到了什麼、又留下什麼。

它只能做三件事：停用嘸蝦米、切成中文、切成英數。 它讀不到你打的字、送不出任何文字、也執行不了任何東西。所以最壞的情況是 被騷擾（有人在你打字時把輸入法關掉），不是資料外洩。

擋住的兩條路：

  1. 只在這台電腦上聽。 同一個網路上的其他機器連不到， 路由器也轉不進來。順帶一提，這樣綁不需要管理員權限，也不會跳出防火牆的 詢問視窗。
  2. 網頁發的請求一律拒。 網頁其實有辦法對你自己這台電腦 發出請求（例如塞一張圖片的網址），雖然它讀不到回應，卻仍然會觸發副作用。 所以規則不是「允許哪些網站」而是「聞起來像瀏覽器就拒」 —— 瀏覽器每一個請求都會帶上某些標頭，而正常的接線工具一個都不會帶。 這也是為什麼你不能用瀏覽器測試它。

剩下的風險：同一台電腦上的其他程式可以切你的輸入法。 這是刻意收下的。那種程式如果已經在你機器上跑，它要偷看你打的字有的是 辦法，切輸入法是它能做的事裡最無害的一件；而換來的是接線設定短到可以 直接印在說明頁上，換一台電腦也不必重抄一串密碼。

不放心的話有兩個選擇：把 vim_port 設成 0 整個關掉，或者只在要用的時候打 ,,vim， 用完再打一次關掉 —— 那本來就是預設的用法。
